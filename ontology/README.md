# ontology/

Put the file exported from Protege here and ensure that the file name matches the
`ONTOLOGY_FILE` value in `.github/workflows/publish-docs.yml` and in
`scripts/build-docs.sh`.

Rules that keep the build and the catalogue submission clean:

1. The ontology IRI must be the namespace you will publish, for example
   `https://w3id.org/myont`. Change it in Protege under
   `Active ontology > Ontology IRI`, not by editing the file afterwards.
2. Always set `owl:versionIRI`, for example `https://w3id.org/myont/1.0.0`.
   Bump it on every release.
3. Give every class, object property and data property an `rdfs:label` and an
   `rdfs:comment` in English. LODE, and therefore WIDOCO, renders these
   directly, and the BE-OLS evaluation checks for machine-readable annotations.
4. Add the header annotations from `metadata-template.ttl`.
5. Turtle is preferred for version control because the diffs are readable.
   The workflow also publishes RDF/XML, JSON-LD and N-Triples, generated by
   WIDOCO, so you do not need to commit those.

Keep previous released versions under `ontology/releases/1.0.0/` if you want the
older serialisations to stay resolvable.
